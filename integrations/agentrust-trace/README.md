# REMORA as an AgenTrust TRACE external-evidence-source

Status: experimental, milestone M1 of REMORA-SDD-TRACE-001. Not submitted to
AgenTrust, not reviewed by AgenTrust, no TRACE conformance level claimed.

## What it does

`remora.interop.trace.map_result` takes one signed REMORA federation result
(`remora-federation-result-evidence-v1`, from `remora/federation/results.py`).
It verifies the result with REMORA's own `verify_result`, against keys the
caller supplies and the exact subject the caller names. It then maps the
result into the shape of a TRACE v0.2 record. If the envelope does not verify, nothing is mapped and the caller
gets a refusal code and reason.

The output is a mapping, not a TRACE Trust Record. AgenTrust ruled on the same
case for APS in [agentrust-io/integrations#170](https://github.com/agentrust-io/integrations/issues/170).
A record without `model`, `data_class` or `build_provenance` is not a Trust
Record, and those fields must not be invented. A producer mapping signed
evidence from elsewhere declares `trace_roles: [external-evidence-source]`
with no conformance level. Nobulex, aeoess-aps and probityai-observed-effect
declare the same role.

## Field mapping

| TRACE field | Source | Present |
|---|---|---|
| `eat_profile` | constant `tag:agentrust-io.com,2026:trace-v0.2` | always |
| `iat` | caller's issuance time, not the execution time | always |
| `origin` | `third-party-control-plane`, producer, `<operation>/<report>`, ingestion time | always |
| `appraisal` | `status: none`, verifier named by the result's signing key | always |
| `model` | `ExecutionContextV1.model_initiator`, only when the context digest is inside the signed report | with a bound context |
| `references` | one pointer to the signed result by digest, rel `remora-native-claim-result` | only when the caller names a resolver |
| `subject` | absent: REMORA names the principal of the action, not a workload SVID or DID | never |
| `runtime` | absent: `measurement` is required even for `software-only`, and REMORA's runtime identity hash is not a workload measurement | never |
| `policy` | absent: no policy bundle digest in the native evidence | never |
| `data_class` | absent: REMORA's data scope does not classify downstream data, TRACE's covers outputs | never |
| `build_provenance` | absent: no SLSA level; the context's build digest is deployment-asserted | never |
| `cnf` | absent: export signing is a later milestone | never |

Values REMORA holds but does not map are kept in the `remora` sidecar under
`available_unmapped`, each with the reason, so the loss is visible. The native
result is copied verbatim; a `CONTRADICTED` result maps and stays
`CONTRADICTED`.

The rel is unregistered on purpose. `condition-appraisal` is the nearest
registered value, but it names an independent check, and a REMORA result signed
by REMORA is not independent of REMORA.

## Fixtures

`fixtures/cases/` holds 12 cases generated by `fixtures/generate.py` from fixed
demo seeds. Three are mappings: established with a bound context,
contradicted, and no context with no resolver. Nine are refusals: wrong
tenant, wrong principal, replaced context, unbound context, untrusted signer,
a result rebound to another report, a tampered envelope, an operation-level
subject, and a report the caller does not hold. Each case carries its inputs and the complete expected
outcome, including refusal reasons, so a consumer can compare everything a case
states.

The keys are demo keys, the reports and contexts are synthetic, and no provider
was called.

## Reproduce

```bash
python integrations/agentrust-trace/fixtures/generate.py --check
python -m pytest tests/test_trace_export_mapping.py -q
```

The tests validate every emitted field against the TRACE schema vendored in
`upstream/trace-claim.json`, pinned in `upstream-lock.json` to trace-spec
`4c7d6ec`. They check that the full schema refuses the mapping on exactly the
absent fields, and that no unjustified REMORA value reaches a TRACE field. Expected outcomes are written in the test by hand, not read back from
the fixtures.

## What this does not establish

It does not produce or sign a Trust Record, and it has not been run through
`agentrust-trace` or `trace-verify`. A mapping shows that REMORA's signed result
verified under the keys the caller chose and was bound to the subject the
caller named. It says nothing about whether the result describes what happened,
and nothing about the executed effect. Independent verification and runtime
capability surface completeness stay `NOT_ESTABLISHED`.

## Open questions for AgenTrust

1. Is there a legitimate `runtime.measurement` for a `software-only`
   control-plane import? aeoess-aps uses the digest of the signed decision;
   this mapping leaves `runtime` out until that is settled.
2. Would AgenTrust accept a REMORA result as `condition-appraisal` when the
   checker is the producer, or should it stay an unregistered rel?
